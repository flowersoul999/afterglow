# 后台混合内容批量提交设计

日期：2026-11-07

## 目标

站长可以在 `/admin` 连续新建文章、说说和更新日志，把它们加入同一个待提交队列，最后一次性写入 GitHub。整批内容只产生一个 Git 提交，只触发一次 GitHub Pages 构建。

## 交互

- 新建内容时保留“直接提交”，新增“加入待提交”。
- 加入队列后继续创建下一条内容，不立即访问 GitHub。
- 顶栏显示待提交数量，点击打开队列面板。
- 队列允许混合不同集合，支持重新编辑、移除和清空。
- 队列保存在 `sessionStorage`，刷新页面后仍在，关闭标签页后清除。
- 每批最多 30 条；第一版只处理 Markdown 内容，不上传本地图片文件。
- 提交失败时保留完整队列；成功后清空队列并刷新当前集合列表。

## 数据流

1. 编辑器把表单值写回 `ContentDoc`。
2. 内容仓库层序列化 Markdown，生成基础目标路径。
3. 队列保存集合、标题、分类、基础路径和完整 Markdown。
4. “提交全部”调用 `/api/github/batch`。
5. Worker 读取目标分支当前提交与树，给重名路径追加 `-2`、`-3`。
6. Worker 创建多个 Blob、一个新 Tree、一个 Commit，再原子更新分支引用。
7. 分支更新冲突时基于最新分支自动重试一次。

## 一致性与错误处理

- Worker 只接受 `src/content/` 下的 Markdown 路径。
- 请求最多 30 项，所有字段在写 GitHub 前统一校验。
- Git Tree 返回截断时停止提交，避免基于不完整路径集合覆盖重名文件。
- 任一 Blob、Tree、Commit 或 Ref 更新失败时，前端队列不清空。
- 只有 Ref 更新成功才视为整批提交成功。

## 验证

- Node 测试覆盖队列恢复、更新、数量上限、路径避让和单提交 Git 数据链路。
- 运行 `pnpm type-check`、`pnpm check`、`pnpm build` 和 Biome CI。
- 浏览器验证桌面与移动端的加入队列、重新编辑、移除和提交反馈。
