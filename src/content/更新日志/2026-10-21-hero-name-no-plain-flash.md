## 首屏大标题直接以 Hatching 样式出现

**现象**：刚进首页时大标题先以「无纹理的纯彩色字」闪一下，然后才变成铅笔纹理的成品。站长确认：宁可刚进来时暂时没有标题，也不要那个丑的中间态。

**原因**：铅笔纹理是 WebGL 后处理（`HatchEffect` + vfx-js），从页面首帧到画布画出第一帧之间有空窗，这段时间 DOM 里的裸彩虹字原样可见。

**修复**：

1. 标记里直接给 `.home-hero__name` 写死 `is-hatch-pending`（CSS `opacity: 0`，首帧就藏），不依赖模块脚本加载后才加类——彻底消灭脚本加载间隙的闪现。
2. `initHeroHatch` 在 `vfx.add()` 成功、渲染循环画上第一帧之后，把状态类摘掉。**摘掉后不做任何淡入动画**——vfx-js 接管时会把 DOM 文字用内联 `opacity: 0` 藏起来、只显示画布；任何带 forwards 填充的 CSS 动画都会覆盖这个隐藏，把平滑彩虹字放回来叠在纹理上（第一版修复就栽在这里，表现为"白色密纹"的怪样式）。
3. 兜底，任何路径都不会让标题永远空白：减弱动效 → 静态显示；WebGL 初始化失败 / `vfx.add` 抛错 → 淡入显示静态彩虹字；3 秒超时 → 强制淡入；`<noscript>` → CSS 强制显示。
4. 其余入场动画（职业、徽章、取景框、对话框等）不受影响，照常播放。

**验证**（Playwright 逐帧采样，dev server）：平滑 DOM 彩虹字**全程 0 帧可见**；结束时元素内联 `opacity: 0`（vfx 接管）、状态类无残留、画布挂载正常；对标题区域截图做像素统计，26.7% 高饱和彩色像素 / 112 个色簇——彩色铅笔纹理渲染正常，样式与改动前一致。`astro check` 0 错 0 警。
